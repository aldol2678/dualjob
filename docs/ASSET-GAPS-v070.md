# 겸직금지! 0.7 에셋·타이포그래피 점검

**후속 제작 완료:** 같은 날 승인 후 전용 이미지 14종·SVG 8종·WOFF2/타이포 정리를 0.7 로컬 후보에 반영했습니다. 아래는 제작 전 조사 기록입니다. 현재 결과는 [에셋 문서](ASSETS.md#v07-신규-에셋--로컬-후보)를 참조하세요.

조사일: 2026-10-29. 대상: 로컬 0.7 후보 `689af20`. 이번 조사는 런타임·그림·폰트를 운영에 반영하지 않았다.

## 확인 결과

0.7 구현에서 새 이미지 생성은 없었다. 카드 16종과 유물 8종은 기존 그림 매핑을 재사용했고 재고 감사관·겸직 심사관은 계약서 악령 초상화를 공유한다. 과거 0.6.17 문서의 이미지 제작 수단은 image_gen, 에셋팩토리 역할은 메타데이터 검수였다.

현재 `src/assets` 파일 80개, 합계 5,701,140바이트(소스 JS·CSS 포함). 래스터 이미지 65개 디코딩 성공, JS/CSS의 이미지·폰트 참조 중 없는 파일 0개. 파일 누락과 전용 그림 부재는 구분해야 한다.

폰트 3개 합계 3,077,700바이트(약 3.08MB), 전체 에셋 폴더의 약 54.0%다. 이 비율은 압축 전 파일 합계이며 실제 첫 화면 네트워크 전송 비율은 측정하지 않았다.

| 파일 역할 | 포함된 굵기 | 파일 바이트 |
|---|---|---:|
| Pretendard Regular | 400 | 1,045,232 |
| Pretendard Bold | 700 | 1,067,708 |
| Gmarket Sans Bold | 700 | 964,760 |

게임 소스에 등장하는 고유 한글 음절 555개는 세 폰트가 모두 지원한다. 반면 ⚡·🪙·📦·✦·☾ 같은 기호는 포함하지 않는다. Gmarket Sans에는 −·✓도 없어 대체 폰트에 의존한다. 이것만으로 모든 기기에서 깨진다고 단정할 수는 없지만 기기별 그림·기호 모양을 보장할 수 없다. CSS는 750·850·950 등 실제 파일에 없는 굵기도 요청한다.

## 전용 그림 제작 대상

- 영혼세무사: 영혼 담보권 — 사슬로 묶인 영혼과 담보 서류.
- 황금회계사: 금본위 적립 — 장부에서 증류기로 이동하는 금화.
- 지옥주방장: 지옥 숙성장 — 봉인 항아리와 저주 연기.
- 마도셰프: 교차 플레이팅 — 재료와 시약을 양쪽에서 조합하는 접시. 기존 연금 연회와 같은 잔칫상 그림 피하기.
- 유물: 담보 봉인, 복리 주판, 숙성 국자, 쌍둥이 식기, 겸직 출입증, 여분 주머니, 마지막 서류철, 공용 업무함.
- 적: 재고 감사관(재고표·계량 도구), 겸직 심사관(두 계열을 심사하는 도장·서류).
- 기본 직업 카드: 분할 상환, 연결 장부, 이자 청구, 대량 손질, 약불 유지, 한입 서비스, 저주 각인, 저주 청산, 그림자 피난처, 농축 원액, 반응성 보호막, 회수 플라스크.

기존 규격인 카드 384×176, 유물·초상화 256×256을 우선 유지한다. 작은 화면을 기준으로 중심 사물 1개, 굵은 외곽선, 글자 없는 투명 배경을 사용한다. 파일 규격 통과와 112px 카드/48px 유물에서의 시각 구분 검수는 별개다.

## 폰트 후보와 권고

1. **현재 Pretendard + Gmarket 유지·정리(우선)**: 현재 한글 글리프 누락은 없으므로 바로 다른 서체를 늘릴 이유가 약하다. 400/700 역할 정리와 작은 UI 가독성·아이콘 개선을 먼저 한다.
2. **Pretendard Variable**: 공식 배포에 가변 폰트와 동적 서브셋이 있다. 여러 굵기가 필요할 때 후보. 가변 파일 자체가 항상 더 작지는 않으므로 현재의 두 정적 파일과 비교해야 한다. 로컬 제공으로 외부 CDN 필수 의존을 만들지 않는다.
3. **SUIT Variable**: 공식적으로 UI 본문용 서체로 소개하며 WOFF2 가변 배포가 있다. 기존 Pretendard와 같은 화면·크기로 비교할 대안.
4. **Wanted Sans**: 공식 프로젝트의 형태가 다른 산세리프 대안. 장식용 폰트를 추가하기보다 본문 대체 후보로 비교한다.

WOFF2 변환 크기 측정은 로컬 Brotli Python 모듈 부재로 실행하지 못했다. 절감률을 추정해서 제시하지 않는다. 서브셋을 적용한다면 신규 카드/이벤트 텍스트가 추가될 때 자동 재생성과 글리프 검사가 필요하다.

## 에셋팩토리에서 확인한 범위

연결된 Asset Factory 도구의 capabilities는 브라우저 스튜디오 5.4, 메타데이터 검수, 절차적 효과음·BGM 생성을 보고했다. 현재 연결 도구에는 이미지 생성이나 사용자 브라우저의 에셋 목록을 읽는 기능이 노출되지 않았다. 도구가 브라우저에 있는 모든 기능을 대표한다고 간주하지 않는다.

이번에는 로컬에서 측정한 이미지 75개(래스터 65+SVG 10)의 파일명·크기·SHA-256을 `audit_preview`에 전달했다. 배포 기준 상대경로 `assets/...`로 메타데이터 구조 PASS. 처음 전달한 `src/assets/...` 경로는 INVALID_ARGUMENT이었고 수정 후 성공했다. 도구 응답은 files_read=0, writes=0, persisted=false이며 실제 바이트·시각·엔진·권리 검증은 UNKNOWN이다. 성공 기록은 `asset-audit-v070.json`에 보존했다.

이미지 제작은 image_gen으로, 필요한 효과음은 에셋팩토리의 절차적 생성으로 진행하고, 실제 파일 검수·게임 연결은 별도로 확인하는 구성이 현재 가능한 경로다. 이번 조사에서는 새 생성·배포를 실행하지 않았다.
